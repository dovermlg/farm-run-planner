# Local packaging harness (development only)

`LocalHubCheck.java` is the small harness used for the 1.10.0 review. It is not a plugin, is not in a production source set, and is not included in the runtime JAR. Its package grants access to the official packager's package-private source-directory field. It does not bypass `Plugin.build` checks or call the downloader/uploader.

Build the official `plugin-hub-tooling` API recorder and packager at commit `034eaffd5bce7bb678d35287b547874f3dba6b3b`. Use the official runtime layout containing `gradle/` (8.10), `target_init.gradle`, `apirecorder.jar`, `package.jar`, the Plugin Hub dependency-verification metadata, `plugin-hub/runelite.version` (1.13.2), and the dependency API file generated by the tooling's preparer. The standard builder and init script come from that tooling, not from this plugin's build script.

Compile this harness against `package.jar`. Run it with the source project path, report-directory path and local marker-file path as its three arguments, with the runtime directory as the working directory. Set `java.io.tmpdir` to an empty scratch directory that you control. The official packager uses and cleans its temporary build directory; the source project is copied and is never modified by the harness.

The local marker file is named `farm-run-planner`. For this review its parser fixture contains `repository=https://github.com/LOCAL-OFFLINE-CHECK/farm-run-planner.git` and an all-zero 40-character commit. The marker must be tracked in a temporary local Git repository because the packager checks its Git history. Those values are deliberately fictional and must never be submitted to Plugin Hub. The real-source download step is not tested. See `docs/HUB-REVIEW.md` for results, limits and actual submission steps.

A successful check copies the built JAR, API record, source ZIP and packager log to the requested report directory. It also compares recorded API usage with the RuneLite dependency API. This is a local preflight, not hosted Plugin Hub CI or maintainer approval. Cached dependency preparation may be necessary when the official tool's child environment cannot use the host's network configuration. Do not disable dependency verification to work around download problems.
